## 编排铁律（本会话验证过的模式）

1. 主会话只做：划分批次 → 写自包含派单词（SPEC 摘录+文件清单+验收标准+汇报行数上限）→ 派 subagent → 对照 SPEC 验收 diff → `node scripts/review-mark.js done` → commit+push → 批次汇报（含临时文件清单，target/ 每批清）
2. subagent：写码+自测（`mvn verify` 绿），**禁止 git 操作**；越界即停汇报
3. 换窗/暂停前：不留在途 subagent；有半途工作就写 handoff 档案（b7-handoff.md 模式）
4. hook 已 v2（委托 spotless + 播报去重 + 在途防护）；门禁流程照 AGENTS.md
5. 版本：v1.1 完成后里程碑即版本（`1.1.0`），发布遵循 docs/RELEASE_PROCESS.md（push→CI 绿→打 tag）
6. **链式交接**：v1.1 收口时（打完 1.1.0 tag）由当值会话写 `.scratch/jauth-hub/v1.2-kickoff.md`（现状快照 + 滑账清册 + 本铁律第 6 条原样自续），此后每阶段同理。永久路线图永远在 docs/SPEC.md §5——kickoff 只管当前一窗，SPEC 才是二三四期的全量底账
