## 实战教训(v1.4 付费买来的,新会话直接受益)

- **AuthenticationManager 不可经 `AuthenticationConfiguration#getAuthenticationManager()` 暴露为 bean**:全局构建器会把它惰性解析为自身 parent,无人认领的 token 落 parent 即无限自递归(PatIntrospection/RpLogout StackOverflow 实证)——正确做法:自组装 DaoAuthenticationProvider 的 ProviderManager(无 parent)+ 上下文感知 DefaultAuthenticationEventPublisher(事件源照 AuthenticationConfiguration 同款,javap 验证)
- **CSRF 契约**:默认 XorCsrfTokenRequestAttributeHandler 接受状态面返回的**原始 token** 经 `X-CSRF-Token` 头与 `_csrf` 表单参数双通道(真链探针 + 阴性对照钉死);登录成功后 token 换发(CsrfAuthenticationStrategy),headless 皮每页重取状态面
- **auth_time 取数链路**(javap 实证):DaoAuthenticationProvider 附加 FACTOR_PASSWORD FactorGrantedAuthority(issuedAt=认证时刻)→ SAS JwtGenerator.getAuthenticationTime 读之;手工认证桥原样持久化 authenticate() 结果即保真
- **copy-resources 对缺失源目录静默成功**(实测)——依赖产物存在性的 Maven profile 必须 enforcer requireFilesExist 兜底,不兜即静默出无皮制品
- **v1.3 及更早教训仍有效**(详见 v1.4-kickoff):javap-over-memory、Boot 4.1 非索引 session 仓库、族谱表 FK 级联、redirectUri 追加语义、consent 表实名、PS 5.1 批量替换误伤、locale 钉死、MockMvc standalone 无视图渲染、限流测试时序敏感、每批评审平均修出 1-3 条真问题
- **网络瞬断成常态**(v1.4 两次):push 失败挂后台 60s 重推循环,不阻塞下一批;`git status -sb` + `ls-remote` 对账
- **主会话门禁指纹顺序**:评审实体完成后先 `review-mark done` **再**跑 git 链(链式 `mark && add && commit` 会被 PreToolUse 门禁整条拦下)
