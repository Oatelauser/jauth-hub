## 编排铁律(v1.1/v1.2 全程验证过的模式,原样自续)

1. 主会话只做:划分批次 → 写自包含派单词(SPEC 摘录+已核实接线事实+文件清单+验收标准+汇报行数上限)→ 派 subagent → 对照 SPEC 验收 diff → `node scripts/review-mark.js done` → commit+push → 批次汇报(含临时文件清单,target/ 每批清)
2. subagent:写码+自测(`mvn verify` 绿),**禁止 git 操作**;越界即停汇报
3. 换窗/暂停前:不留在途 subagent;有半途工作就写 handoff 档案(b7-handoff.md 模式)
4. hook 已 v2+(格式化委托 spotless + 播报去重 + 在途防护 + 在途推迟);门禁流程照 AGENTS.md
5. 版本:里程碑即版本,发布遵循 docs/RELEASE_PROCESS.md(push→CI 绿→打 annotated tag;**tag 永不移动**)
6. **链式交接**:v1.3 收口时由当值会话写 `.scratch/jauth-hub/v1.4-kickoff.md`(现状快照 + 滑账清册 + 本铁律第 6 条原样自续),此后每阶段同理。永久路线图永远在 docs/SPEC.md §5——kickoff 只管当前一窗

## 实战教训(v1.2 付费买来的,新会话直接受益)

- **API 配额会杀死在途 subagent**(429):派单词写成"自包含+可代执"形态,主会话照单无缝接手(C3 已验证此预案)
- **review-mark 与 git 提交必须分两次工具调用**:git 门在 PreToolUse 拦截,标记+提交挤同一条命令会让标记来不及落盘(C4 教训)
- standalone MockMvc 无视图解析器 → 视图名渲染循环派发;控制器单测直接调方法断言模型即可,别起 MockMvc(C3 教训)
- by-type 取 `RequestMappingHandlerMapping` 会撞 actuator 的 `controllerEndpointHandlerMapping`(其子类)→ 用 `ObjectProvider.stream()` 流式遍历(C4 教训)
- H2/PG 多列 ADD COLUMN 无双兼容单语句写法 → 逐列一条 ALTER(C1 教训)
- v1.1 教训仍然有效:locale 敏感断言钉 locale;二进制列 Base64 TEXT;循环内逐行反查=p3c 强制项;每批评审平均修出 1-2 条真问题,交付门禁 AI 全量评审不可省
